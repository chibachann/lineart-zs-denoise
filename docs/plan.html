研究の問い

仮説

何が起きると予想しているか

基準にする手法は Zero-Shot Noise2Noise（ZS-N2N, CVPR 2023）です。ノイズ画像を 2×2 のマスごとに「左上と右下の平均」「右上と左下の平均」の2枚に間引き、片方からもう片方を予測するよう小さなネットを学習します。2枚は同じ絵に別々のノイズが乗ったもの、とみなせるという前提に立っています。写真のようになめらかな画像ではこの前提がほぼ成り立ちますが、1ピクセル幅の線ではそうとは限りません。

向きの偏り

斜め 45° の細い線は、間引いた2枚の片方にだけ写り、もう片方には写らない。ネットはそれを「ノイズ」として学び、斜めの細い線だけが薄くなる・途切れる。縦横の線では起きにくい。

太さの依存

線が細いほど（1〜1.5px）この影響は強く、3px 以上ではほぼ消える。線幅と向きで線の残り方を表にすると、はっきりした傾向が出る。

直せる

間引き方を線の向きに合わせる、間引き方を複数混ぜる、線の周りの誤差を重く数える、などの工夫で、写真での性能を落とさずに線の残り方を改善できる。

評価の基準

「良くなった」と言うためのルール

項目基準理由
主指標（全体）PSNR（dB）と SSIM。画像は中央 256×256 を切り出し、値域 [0,1] で計算ZS-N2N 論文と同じ条件で、論文の数値と直接比べるため
主指標（線）線の再現率：正解の線を細線化（骨格化）し、そのうち除去後の画像を2値化した線で覆われている割合。ほかに線の適合率と clDicePSNR は面積の大きい背景に支配され、細い線の消失を見落とすため
補助指標線上の PSNR（正解の線を 2px 太らせた領域だけで計算）、線の濃さの保持率（線上の平均の濃さ ÷ 正解の濃さ）、向き別（0°・22.5°・45°…）の再現率仮説「向きの偏り」「太さの依存」を直接確かめるため
改善の判定同じ画像・同じノイズで比べ、画像ごとの差に Wilcoxon 符号順位検定を行い p < 0.05。平均と標準偏差を必ず併記平均値の小さな差を偶然と区別するため
乱数ノイズは固定シードで事前に作って保存し、全手法で同じものを使う。ネットの初期値は 3 シードで平均比較の公平さと再現性のため
写真での性能Kodak24・McMaster18 で ZS-N2N からの低下 0.1 dB 以内線画専用にして一般性を失っていないことを示すため
速さ256×256 の1枚あたりの時間（Apple M4 の CPU）。ZS-N2N の 2 倍以内「軽くて速い」という手法の長所を保つため
新手法の案

試したい工夫（優先度順）

間引き方を混ぜる

D1/D2 の組み合わせを、斜め2通りに加えて「横に並んだ2画素」「縦に並んだ2画素」も使い、学習の反復ごとにランダムに選ぶ。どの向きの線も、どれかの組み合わせでは両方に写る。Neighbor2Neighbor（2021）のランダムな近傍選びに近い発想を、ZS-N2N の軽さのまま取り入れる。

優先度 高・実装が簡単
線の向きに合わせて間引く

ノイズ画像から局所的な線の向き（構造テンソル）を推定し、線に沿った2画素を組にして間引く。線は両方に同じように写り、ノイズだけが独立になる。「間引き方を混ぜる」より狙いを絞った版。

優先度 高・本命候補
線の周りの誤差を重く数える

損失を、エッジの強さで重み付けする。エッジはノイズ画像を軽くぼかして求める（正解は使わない）。線を消す方向の学習にブレーキをかける。

優先度 中
回転・反転の平均

画像を 90° 回転・左右反転した8通りで除去して平均する（テスト時の拡張）。向きの偏りを打ち消す、最も簡単な比較用の手法。「間引き方を混ぜる」「線の向きに合わせて間引く」がこれより良いことを示す必要がある。

優先度 中・比較用
墨と紙の2値性を使う

線画は「墨の色」と「紙の色」にほぼ分かれる。出力をパレット（k-means で推定した数色）へ近づける弱い正則化を加える。テーマ F（AI 画像の色ムラ）にもつながる。

優先度 低・「線を守る改良」の後
相関のあるノイズへの対応

紙の質感や JPEG のノイズは隣の画素と相関するので、2×2 の間引きの前提が崩れる。間引きの間隔を広げる、Median2Median（2025）の考え方を取り入れる、などを「実スキャンへの拡張と報告」の段階で試す。

優先度 低・実スキャンの段階で

読み取れること

ポアソンは論文と ±0.1 dB 以内でほぼ一致。ガウスは全条件で 0.1〜0.3 dB 低く、Kodak24 σ=25 は基準ぎりぎりです。ガウスだけ一様に低いので、ノイズを [0,1] に切り詰める扱いの違いが疑わしい。シードを増やした確認と合わせて、「線の壊れ方調査」の前に 1 回だけ切り詰め無しでも測ります。

実行時間（256²、1枚）

Apple M4 の GPU（MPS）：約 42 秒（2 本同時だと 50〜65 秒）。kind 上のコンテナ（CPU 4 コア上限）：約 240 秒。Apple M4 の CPU を 3 並列で回すと 1 枚 300 秒超。論文は GPU 20 秒・i9 CPU 80 秒。

まだやっていないこと

BM3D の比較はまだ（「線の壊れ方調査」でまとめて流す）。シードは 1 つだけなので、ばらつきの幅は未計測。仮説「向きの偏り」（斜め 45° の 1px 線は間引いた片方にしか写らない）は、間引きの部分だけ単体テストで確認済み。

データと指標

何で測るか

写真（再現用）

Kodak24（24枚）と McMaster18（18枚）。中央 256×256 を切り出す（ZS-N2N 論文と同じ）。

合成線画（自作ベンチマーク）

プログラムでベジエ曲線・直線・円を描いて作る。線幅・向き・アンチエイリアスの有無・塗りの有無を制御でき、正解が厳密にわかり、権利の問題もない。256×256 を 100 枚以上。

手描き線画

Quick, Draw! のストロークデータを描画して使う（CC BY 4.0 とされているので、使う前に条件を確認する）。さらに自分で描いた線画を 10〜20 枚。

線の指標の考え方

文書の2値化の評価（DIBCO の pseudo-F-measure）は、細い文字の骨格がどれだけ残ったかを測る。同じ考え方を線画に当てはめる。clDice、Skeleton Recall も参考にする。

  4. 論文の数値と自分の数値は、常に並べた表で示す（再現の差を隠さない）
  5. うまくいかなかった実験も記録する。「原因の特定」で「線は壊れない」とわかった場合も、それ自体を結果として扱い、計画を見直す
  6. コードは feature ブランチで開発し、main へのマージはあなたが確認してから行う
